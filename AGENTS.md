# AGENTS.md

Stable instructions for humans and AI agents working on Clip5. Read this first, then `tasks.md` for current work.

## Purpose

Clip5 is a small, always-on-top desktop app with five text slots. Each slot has a Copy button that copies its text to the system clipboard. Slots can be edited or pasted into at any time, and their contents are saved automatically.

## Scope

- Desktop app for Windows (primary) and macOS.
- Rust with `eframe`/`egui` (glow/OpenGL backend for a small executable).
- Distributed as a single-file Windows `.exe` and a zipped macOS `.app` via GitHub Releases. Both are built manually by the maintainer (Windows on the PC, macOS on a Mac); there is no CI.
- Project website built with Quarto and published to GitHub Pages from `docs/`.
- Public repository, MIT licence.

## Deliverables

- `Clip5-<version>-windows.exe` (built by `scripts/build_windows.ps1`)
- `Clip5-<version>-macos.zip` containing a universal, ad-hoc-signed `Clip5.app` (built on a Mac by `scripts/build_macos.sh`)
- Project website (GitHub Pages)
- A `CHANGELOG.md` entry for every release

## App Conventions

- Keep the window small. No maximize button; minimize and close only.
- The window resizes freely, but never smaller than five two-line slots. On first launch it opens at that minimum height, fitted to the content at runtime.
- Slots share the window height evenly (at least two lines each). Unfocused slots elide extra text with "…"; focused slots scroll. Losing window focus ends editing. Copy always copies the full text; the × in a slot clears it.
- Pasted text is trimmed of surrounding whitespace; typed text is never changed.
- If the saved window position is off every monitor, open centred on the primary monitor.
- "On top" is a user setting (default on).
- Exactly five slots unless the scope is changed explicitly.
- Data file: `clip5.json` in the per-user data directory (`dirs::config_dir()`). It holds the slots, the "On top" setting, and the window position and size; Clip5 keeps no other state files:
  - Windows: `%APPDATA%\Clip5\`
  - macOS: `~/Library/Application Support/Clip5/`
- Save on edit (debounced) and on close. Write atomically (temp file, then rename). If the file is missing or corrupt, start with empty slots and do not crash.
- On Windows, release builds must not open a console window (`#![windows_subsystem = "windows"]`).
- The single source of truth for the version is `version` in `Cargo.toml`.
- The app links to Buy Me a Coffee (`https://buymeacoffee.com/pbeens`) and GitHub Issues (`https://github.com/pbeens/Clip5/issues`).
- Keep dependencies few. Ask before adding a crate.
- Run `cargo fmt`, `cargo clippy -- -D warnings`, and `cargo test` before considering code work done.

## Rules for Agents

- Keep this file concise and durable. Do not turn it into a session log or changelog.
- Store active plans and changing tasks in `tasks.md`. Update it after a task is completed and verified.
- Record every program-related user prompt in `prompts.md`: newest at the top, paraphrased, with a local timestamp, a goal line, a summary, and the hostname. Add a technical-context line when useful. Do not log administrative or meta prompts.
- Record user-facing changes under `## [Unreleased]` at the top of `CHANGELOG.md`, adding that section if it isn't there (Keep a Changelog format, Semantic Versioning).
- Ask before major structural changes: new top-level folders, new dependencies, a different GUI toolkit, or a different build tool.
- Put shared scripts in `scripts/`, never in the root.
- Every new organizational folder gets a short `README.md`. When adding or moving a document, update the nearest README or index so nothing is left unlinked.
- When the structure changes, update the folder map above.
- Do not commit, push, tag, or publish releases without explicit approval.
- Do not edit `docs/` by hand.

## Skills

- Reusable workflows live in `skills/<name>/SKILL.md` and are listed in `skills/README.md`.
- When the same multi-step task comes up more than once, propose a new skill instead of repeating it ad hoc.
